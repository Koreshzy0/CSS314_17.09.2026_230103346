## Core rules
| Law | Formula | Fixed quantity | Limit |
|---|---|---|---|
| Amdahl | $S_A=1/(s+(1-s)/P)$ | problem size | $1/s$ |
| Gustafson | $S=P-\alpha(P-1)=\alpha+(1-\alpha)P$ | runtime | none; slope $1-\alpha$ |
| Efficiency (Gustafson) | $E=1-\alpha(P-1)/P$ | | $\to 1-\alpha$ |
| Efficiency (Amdahl) | $E=1/(sP+1-s)$ | | $\to 0$ |
| Sun–Ni | $S^*=\dfrac{f+(1-f)G(P)}{f+(1-f)G(P)/P}$ | memory | $G=1$: Amdahl, $G=P$: Gustafson |
| With communication | $S_C=\dfrac{P-\alpha(P-1)}{1+C(P)}$ | | $E\to0$ if $C(P)$ grows |
| Isoefficiency | $W(P)=\Theta(P)$ for Gustafson-compliant code | | optimal |

Key identities: the two laws are the same algebra with different serial fractions,
$f=\alpha/(\alpha+(1-\alpha)P)$ (Task 03); the serial fraction should be measured on the parallel machine.

## Results at a glance
* α = 0.04: E = 0.9625 (P=16) → 0.9600 (P ≥ 1024); S(16384) = 15,728.68 (Task 06).
* P = 8192, S ≥ 7500 ⇒ α_max = 692/8191 = 0.08448 (Task 07).
* s = α = 0.08, P = 128: Amdahl 11.47 vs Gustafson 117.84 (10.27×) (Task 08).
* α = 0.08 (phases A+B): S(512) = 471.12, S(2048) = 1884.24 (Task 09).
* Memory cap 32 GiB/node, 16 B/point: N ≈ 5,161 (64 nodes), ≈ 10,321 (512 nodes) (Task 10).
* GEMM: N ∝ P^{1/3}; stencil: comm/comp constant = 6/n; N-body: direct N ∝ √P, Barnes–Hut N ≈ linear in P.
* Energy: parallel run costs $P_{idle}\,\alpha(P-1)\,T$ extra versus serial (Task 15).

## Design guidelines
Design for weak scaling when: (1) the application has a tunable resolution/size and a time budget; (2) the work per
unit of data is regular and the communication is nearest-neighbour (surface/volume constant); (3) non-scaling parts
(I/O, seeding, setup) are O(1) or O(log P); (4) the problem still fits in memory at the largest P.
Prefer strong-scaling thinking (Amdahl) when the problem size is fixed by the science/customer, when iteration counts
grow with size (CFL, Krylov), when global communication dominates, or for irregular graphs (Tasks 13, 20).
Always validate with a measured α(P), not a single α.

## Architectural synthesis
1. Remove O(P) serial pieces (seed generation, rank-0 I/O, flat reductions) — they dominate α at scale (Task 19).
2. Keep communication local; use tree/hierarchical collectives; overlap halo exchange with compute (Tasks 12, 17).
3. Watch memory per node: N ∝ P^{1/3} for 3D grids; the memory ceiling ends weak scaling (Tasks 10, 11).
4. Measure on the real machine: turbo, heterogeneous cores, thermal limits and NUMA bend the curve (Task 24).
5. Judge algorithms by time-to-solution, not by scalability alone (Barnes–Hut paradox, Task 18).
